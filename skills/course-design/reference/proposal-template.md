# Proposal template

Every proposal carries every field. A field with nothing to say states why (for example "none: no generated files").

```
### P<n>: <imperative title>

- type: content | structure | syllabus | tooling
- rubric criterion: <name from rubric.md>
- trace: <CLO or module, as COURSE.md cites them>
- current state: <what exists> (<path:line>, one or more)
- proposed change: <what to do, concrete enough to review>
- affected artifacts: <paths or artifact types from COURSE.md>
- build skill: <skill per artifact, from COURSE.md>
- acceptance check: <observable condition that shows it is done>
- effort: S | M | L
- basis: evidence-based | design judgment
- sources: <URL (checked YYYY-MM-DD), one per field claim; "none: unsourced field claim" for design judgment; else "none: no field claims">
- student data: used (<path:line>) | provided, not used | not provided
- blocked on: <proposal ids; "instructor decision" for L; else "none">
```

Sizing: `S` touches one artifact in one module. `M` touches several artifacts or modules. `L` changes structure (module sequence, assessment mix, or a course-wide foundation such as the language or platform taught, the lab stack or the textbook).

Syllabus and module-structure changes are their own proposals, never folded into a content proposal.
