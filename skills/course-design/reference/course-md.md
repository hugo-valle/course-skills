# COURSE.md fields

`COURSE.md` sits at the repo root and maps one course onto its repo. Use this file to draft it when it is missing. It has one `##` section per row below, in this order, under these headings. A field you cannot find in the repo goes into the draft as `unknown: <question for the instructor>`; never guess one.

| Section | Holds | Read by | Draft it from (e.g.) |
|---|---|---|---|
| Syllabus | Syllabus path; the CLO heading and how CLOs are cited (CLO1–CLOn); the module heading pattern with its objectives, readings and assignments subheadings; the grading and policy sections | Phase 1–2 (CLO trace), `proposal-template.md` (trace) | The root README or a file named `syllabus*`; `grep -n '^#'` it for the CLO, module and grading headings |
| Delivery context | Modality; cadence (release day and time, due day and time); term length and exam weeks; per-module and term workload targets | `rubric.md` Per-module load, Term rhythm | Syllabus schedule and policy sections. A target the syllabus does not state is `unknown` |
| Module layout | Per-module folder pattern; a table of artifact root, source files and generated files per artifact type, then per-artifact notes (embedded copies, hand-written files the rebuild refuses to overwrite); modules with no content; where the syllabus says which module carries each lab; the command that rebuilds generated files | Phase 1 cross-check, `rubric.md` Workload table, `course-implement` Phase 3, `review-module` Phase 1 and 4, `course-content`, `quiz-authoring` (rebuild) | `ls` of the top-level folders; source vs generated from the repo's agent instructions, `.gitignore` and the build skills; modules with no content from syllabus modules that have no folder or are exam weeks |
| Artifact types and build skills | One row per artifact type naming the skill that builds it, plus the syllabus/module-structure row and the one-module review skill | `proposal-template.md` (build skill), `course-implement` Phase 1–2 | the `SKILL.md` descriptions of the course repo's `.claude/skills/` and the global skills, matching each artifact root to the skill that names it. An artifact type with no skill gets build skill `none` |
| Quizzes | Quiz format and conventions doc; file name pattern; kinds (for example practical and theoretical); the question types to draw from; per-objective coverage target; outcomes file; reference sheets for constants. A course with no quizzes writes "none" | `quiz-authoring` | The README under the quiz root; the names and first lines of existing quiz files; the kinds of question already in the banks |
| Lab stacks | One row per stack: language, toolchain, test runner, CI, adapter skill; a lab-contract mapping (the `course-implement` skill's `reference/lab-contract.md`) from each part to a path, with the CLO each lab task traces to; a language check naming excluded folders | Phase 1 cross-check, Phase 2 Labs, `rubric.md` Lab contract, `course-implement` Phase 3 | File extensions under the lab roots, the test files there, `.github/workflows/`, the lab rubric, and the skill whose description names the lab root. A stack with no such skill gets adapter `none` (a gap, not an error). A course with no labs writes "none" |
| Slides | The fixed slides-file front matter (`subtitle`, `author`, `extra` credit line) and the code exercise file extensions | `slide-prep` | The front matter of an existing `moduleNN_slides.md` or SlideKraft export; the extensions of non-Markdown files under the exercise root. A course with no slides writes "none" |
| Figures | The course style layer path and how figures input it; the base-style copy; where a module's readings are listed; the caption citation; a table of colour, base name, layer name and meaning. A course with no figures writes "none" | `add-images` | An existing figure `.tex` and the style file it inputs; the captions in the notes |
| Sources | The sources manifest path (`instructor_material/README.md`, rows `\| id \| kind \| location \| name \|`, kind `pdf` or `url`, git-ignored); the course edition; the citation form used in the notes | `review-module` (Accuracy and Alignment) | The textbook or docs named in the syllabus's required readings; the citations in the notes (`grep -rn '§'`); files under a git-ignored instructor folder |
| Course style rules | Numbered rules `C1`, `C2`, … that the generic style rubric (the `review-module` skill's `reference/style-rubric.md`) leaves to the course: citation form, code block tags and code formatting, quiz title prefix, required note sections, discussion platform and structure; and the conventions docs they come from | `review-module` (Style), `course-content` and `quiz-authoring` (discussion and quiz title rules) | READMEs under each artifact root; the first lines of existing quizzes; the code fences and headings of existing notes |
| Manual stages (outside the repo) | Steps done outside the repo, split into student-facing (cost student time, listed in the order the student does them) and production (instructor only, gate a release) | `rubric.md` Manual and external stages, Workload table, `course-implement` Phase 4 | Syllabus mentions of video, discussion or LMS tools; build skills that stop at a file another tool imports or renders |
| Pointers | Glossary, tracker and triage-label docs, git workflow skill, and any git-ignored material never to quote or stage | Phase 4 (tracker doc), `course-implement` Phase 1 | The glossary file, `docs/agents/`, `CONTRIBUTING.md`, `.gitignore` |

## Drafting

1. Fill every section from its sources, citing the `path:line` or command each value came from beside it in the chat draft (not in the file).
2. Show the whole draft in chat, listing the `unknown:` questions after it.
3. Ask the instructor to confirm or correct it. Write nothing until they confirm. Then write `COURSE.md` without the citations, with their answers in place of each `unknown:`; any they leave open stays `unknown` in the file.
